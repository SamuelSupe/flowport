# Pipeline 사용

[FlowPort 0.2.0](../../README.ko.md) · [사용 안내](https://flowport.pages.dev/ko/docs/pipeline/)

GuanceCloud Platypus Go 실행기를 사용하며 Vector VRL이 아닙니다. 소스, 캔버스, 바로가기 보기는 동일한 유형별 스크립트를 편집하며 .ppl 입출력을 지원합니다. 리소스 로딩 실패는 초안을 유지한 채 재시도합니다. 작업 영역은 최소 600px, 전체는 720px 이상이고 높은 창에서는 뷰포트 80%까지 확장하며 각 패널은 독립 스크롤합니다.

2026-10-20에 격리 환경과 합성 데이터로 0.2.0 릴리스 후보의 영어 화면을 촬영했습니다. 표시된 화면은 0.2.0에 포함되며 촬영 빌드 정보는 이미지 매니페스트에 보존합니다. 주소와 수치는 예시이며 이미지를 선택하면 확대할 수 있습니다.

## 편집과 샘플

1. Pipeline에서 신호 유형을 선택합니다.
2. 소스를 편집하거나 함수, 할당, 조건, 반복 노드를 추가합니다. 모든 보기가 동기화됩니다.
3. 샘플 디버깅을 엽니다. 닫기/Escape는 입력과 결과를 유지하고 원래 위치로 돌아갑니다. 실행 중 닫기는 브라우저 대기를 취소하지만 시작된 서버 실행 중지를 보장하지 않습니다.
4. JSON 객체/배열을 입력하고 필요하면 정리 후 실행 또는 Command/Ctrl+Enter를 누릅니다. 최대 100개이며 하위에 보내지 않습니다.
5. 전후, 출력/필터 수, 이름, Tag, 유형과 나노초 시간을 확인합니다. 여러 출력/자식 Point 유형을 전환하고 단일 입출력의 추가/변경/제거 및 이전 값을 비교합니다.
6. 닫고 수정해 다시 실행한 다음 저장/게시합니다.

처리 전은 디코딩된 Point이지 원시 입력 JSON이 아닙니다. 원시 JSON 복사는 before/results의 숫자 텍스트를 보존합니다. 필드는 페이지당 50개이며 필터 수는 실행기 보고를 사용해 단순 입출력 차이가 아닙니다. 여러 결과는 위치로 대응시키지 않고 소요 시간은 네트워크를 포함합니다.

HTTP json/ndjson/text는 수집 형식이며 샘플은 JSON입니다. 큰 정수와 나노초 텍스트를 유지합니다. 정리는 최대 64단계이며 더 깊은 JSON도 직접 제출할 수 있습니다. 입력/스크립트/유형 변경 후 결과는 오래된 표시가 되고 파싱/실행 실패를 수정해 재시도합니다.

## 버전 및 실패 해제

0.1.16부터 전송 실패는 일반 로컬 큐에 보관하고 1, 2, 4, 8, 16, 32초 이후 최대 60초 간격으로 재시도합니다. 인증, 설정, HTTP413, 속도 제한 및 불완전한 확인도 분기를 유지하며 정상 대상은 독립적으로 전송합니다. 파싱/Pipeline 실패는 입력을 해제합니다. 별도 실패 화면, 부분 재전송, 413 분할 및 수동 재실행은 없습니다.

재시도는 원래 처리 결과, 대상 ID 및 전달 식별자를 유지합니다. 같은 대상 ID로 다시 게시하면 다음 전송 시도에서 새 연결 설정을 사용하며 Pipeline이나 라우팅을 다시 실행하지 않습니다. 새 게시 버전에서 대상을 제거하면 해당 분기는 이전 연결을 유지하고 다른 대상으로 보내지 않습니다. 카운터는 원래 입력 버전에 속하며 대상 저장이나 초안 편집만으로는 대기를 변경하지 않습니다.

processing_failed_batches는 입력 실패, 호환 이름인 sending_failed_batches는 재시도를 포함한 전송 실패 시도 횟수입니다. 전송 실패율은 실패 시도를 실패 시도와 sent_batches의 합으로 나눕니다. overflow_dropped_batches 및 overflow_dropped_bytes는 입력 또는 출력 분기의 FIFO 폐기를 따로 집계합니다. discarded_bytes는 처리 실패와 FIFO 폐기를 포함하며 보관된 전송 실패는 늘리지 않습니다. 수신, 폐기, 카운터 및 순서별 확인은 한 영구 트랜잭션으로 갱신됩니다. 저장 실패는 이전 데이터를 유지하고 새 수신을 확인하지 않으며 재시도는 확인을 완료하지 않습니다. 시작된 요청은 회수할 수 없어 폐기한 분기도 원격에 도달할 수 있지만 큐에 다시 나타나지 않습니다. 시간 초과와 충돌 중복은 여전히 가능합니다.

## Lookup

Lookup은 로컬 불변 데이터를 사용하며 배치별 버전을 고정합니다. 리소스가 없어도 큐 입력을 유지합니다. [Lookup](lookup.md)을 참조하세요. 현재 제어 프로토콜 v6와 체크포인트 형식 3은 조정된 업그레이드와 다운그레이드용 전체 사전 백업이 필요합니다.


## 캐시와 윈도우

Pipeline의 「캐시와 윈도우」에서 예제를 선택해 삽입하고 입력 필드에 맞게 수정한 뒤 샘플을 실행합니다. `cache_get`, `cache_set`, `point_window`, `window_hit`, `agg_create`, `agg_metric`은 `lookup()`, 조건, 라우팅과 함께 사용할 수 있습니다.

제한된 메모리는 **Worker × 흐름 게시 버전 × 입력 데이터 유형**별로 격리되며 같은 범위에서 배치 간 공유됩니다. Worker 재시작이나 이동 시 초기화됩니다. 전역 중복 제거, Worker 간 집계 또는 정확히 한 번 처리를 보장하지 않습니다. 다시 게시하면 새 상태를 사용하며 이전 버전은 수신된 입력을 처리한 뒤 마지막 미완료 집계를 출력합니다. 중지할 때도 같습니다. 1시간 동안 입력 처리에 성공하지 않은 범위는 남은 집계를 출력하고 회수하며, 적중하지 않은 문맥은 버립니다. 흐름을 삭제하면 메모리도 제거됩니다.

미리보기는 매번 별도의 새 상태를 사용하고 샘플 종료 시 미완료 집계를 출력합니다(`stateful_preview=true`). 실행 상태에 접근하지 않습니다. 시간 간격, 배치 간 상태, 재시작 동작은 게시된 흐름과 실제 대상으로 검증하세요.

### 오류 전후 기록 보존

`point_window(before, after, stream_tags=["filepath", "host"])`는 문자열 필드나 Tag로 그룹화합니다. 그 뒤에 `window_hit()`을 호출하여 적중을 표시합니다. `after`는 적중 기록을 포함하고 `before`는 제외합니다. `after=0`은 이전 기록만 복원합니다. 범위 밖 기록은 `drop()`으로 제거합니다. 기록당 `point_window()`는 한 번만 호출할 수 있습니다.

### 윈도우 메트릭 집계

`agg_create(bucket, on_interval="60s", on_count=0, keep_value=false, const_tags=nil, category="M")`는 버킷을 정의하고 시간 또는 기록 수 조건이 충족되면 출력합니다. `"0s"`는 시간 조건을, `0`은 기록 수 조건을 끄지만 둘 다 끌 수는 없습니다. `agg_metric()` 호출 횟수와 무관하게 기여한 기록은 버킷당 한 번만 계산합니다. 개수는 그룹별이 아닌 버킷 전체 기준입니다. 이벤트 시간이 아닌 Worker 처리 시간을 사용합니다. 유휴 상태에서도 약 300ms마다 검사하며 부하로 지연될 수 있습니다.

`agg_metric(bucket, new_field, agg_fn, agg_by, agg_field, category="M")`는 `sum/avg/min/max/set`을 지원하며 `set`은 마지막 값입니다. 그룹 필드나 Tag는 문자열, 집계 입력은 숫자여야 하며 텍스트는 명시적으로 변환해야 합니다. float64 계산이므로 큰 정수나 정확한 소수의 정밀도는 보장하지 않습니다. 버킷 이름은 측정명, 그룹 값은 Tag가 됩니다. `"M"` 또는 `"metric"`은 메트릭을 출력하며 `const_tags`로 고정 문자열 Tag를 추가합니다. 원본 기록은 `drop()`으로 명시적으로 제거하지 않으면 유지됩니다.

### 용량과 실패 동작

| 항목 | 한도 |
|---|---|
| 상태 예산 | 범위당 8 MiB, Worker의 커밋된 상태 64 MiB, 128개 범위 |
| 캐시 | 4,096개 키, 키 1–1,024바이트, 값 64 KiB, TTL 1–3,600초(기본 100) |
| 문맥 | 256개 그룹, before/after 각각 0–128(동시에 0 불가), 키 1–8개, 키 1 KiB·값 4 KiB |
| 집계 | 버킷 16개, 버킷당 그룹 4,096개, 그룹당 필드 64개, 그룹 키 1–8개, 키/출력 필드 256바이트·그룹 값 4 KiB |
| 조건 | 1초–1시간, 1–1,000,000개 기록, 버킷 이름 256바이트 |
| 고정 Tag | 32개, 키 256바이트·값 4 KiB |

예산은 문자열, Point, 인덱스 비용을 보수적으로 계산하며 RSS 한도가 아닙니다. 임시 메모리에는 최대 8개 병렬 배치의 상태 복사본, 디코딩과 출력도 포함됩니다. 잘못된 인수, 누락된 그룹 키, 타입 오류, 용량 초과는 명시적으로 실패하며 일반 Pipeline 정책에 따라 실패한 입력을 해제합니다.

모든 CDC 청크를 포함한 전체 배치 결과가 큐에 저장된 후에만 상태를 커밋합니다. 중간 실패는 부분 변경을 남기지 않습니다. 타이머 출력 저장 실패 시 윈도우를 유지하고 재시도할 때까지 Worker 오류를 표시합니다. 큐에 저장된 출력은 일반 영구 큐로 재전송되고 재시작 후 복구되며 다시 집계되지 않습니다. 메모리의 캐시, 문맥, 집계는 백업되지 않고 재시작 시 손실됩니다. 수신됐지만 미처리된 입력은 빈 상태로 재개되므로 중단 없이 실행한 결과와 다를 수 있습니다.
