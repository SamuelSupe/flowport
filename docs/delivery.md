# 交付、容量与恢复

[FlowPorts 0.5.3](../README.zh-CN.md) · [完整交付指南](https://flowport.pages.dev/docs/delivery/) · [English](https://flowport.pages.dev/en/docs/delivery/)

## 每个阶段代表什么

| 阶段或事件 | 可观察行为 |
| --- | --- |
| 校验、输入容量或持久化失败 | 拒收新输入，不确认接收成功；无可靠应用级确认的协议有自身边界。 |
| 接收成功 | 只确认当前 Worker 的本地持久接受，不等于目标送达。 |
| 解析或 Pipeline 失败 | 记录诊断与持久计数；处理失败可能释放输入。 |
| 所需 Lookup 版本缺失或损坏 | 保留队列并暂停相关处理，尝试恢复资源，不当作普通 Pipeline 失败释放。 |
| 目标发送失败 | 在通道重试额度内保留原处理结果，独立退避；健康目标可继续投递。 |
| 重试额度耗尽 | 原子计数并丢弃未确认分支；无死信载荷、人工重放或自动重新投递。 |
| 输出区域满 | 只淘汰该目标通道最旧的可淘汰分支，保护在途载荷，不挤占其他通道。 |
| 下游确认成功 | 按对应协议记录投递确认，不承诺下游业务处理完成。 |
| 进程重启 | 恢复本地持久队列；远端已接收而本地未确认时可能重复。 |

## 有限重试与故障恢复

首次发送后默认最多重试 **5 次**，可配置 0～100。网络、认证、配置错误与无法确认的回执均消耗额度。耗尽后通道至少等待 60 秒，再试投一个待发送批次；完整成功才恢复，失败继续等待。等待不会消耗其他批次的次数。

历史积压保留失败次数。调低上限可能使已超限积压连续终结；该清理不发送请求、不增加发送失败次数，也不改变原通道退避。调高上限不会恢复已被丢弃的载荷。

修改目标连接后，重新发布引用流并等待 Worker 安装。同一目标 ID 的积压在后续尝试中使用新发布连接，保留原处理结果，不重跑 Pipeline。旧在途请求无法撤回。

目标故障不会自动停止新接入，持续接入与有限存储仍可能导致数据缺口。容量丢弃、重试耗尽和成功投递分别统计，不能相减为唯一输入损失率。确认丢失可能造成重复，不保证严格只发送一次、全局顺序或跨目标事务。

## 固定容量隔离

新数据流默认每 Worker 256 MiB、500 个内部批次，分配给公共输入区与各目的端输出区。全部预留与旧积压须同时符合节点字节预算和 10000 批次上限。既有明确配额不自动改变，各区域不能借用容量。

输入区或游标元数据不足时拒收；输出满时仅影响所属通道。缩容保留旧积压并排空，输出区超额期间可能丢弃新生成的该分支。逻辑配额不等于物理磁盘占用；日志、检查点和回收均需余量。

升级旧队列前，在每个 Worker 的**完整备份副本**上执行官方容量预检；预检可能更新副本，不应指向生产数据目录。它不能代替真实 Worker 安装确认或载荷完整性检查。配置、配额或载荷不满足迁移要求时保留积压并暂停相关新接入。

## Worker、Lookup 与内存状态

各 Worker 使用独立本地持久队列，不跨节点复制。节点磁盘永久丢失后，本地未发送数据无法从其他节点恢复；多个 Worker 不等于多副本队列。

批次入队时固定 Lookup 不可变数据版本，处理时本地匹配，后台同步不会改写已入队批次。已处理的发送积压重发原结果，不再执行 Lookup 或 Pipeline。

缓存、上下文和未输出聚合为有界内存，按 Worker、流版本和输入类别隔离，重启清空。已入队的聚合结果由持久队列恢复。单流配置导出不包含队列、游标、Lookup 数据或内存状态，不能替代完整备份。

更早版本遗留的隔离失败载荷需按[官方离线维护步骤](https://flowport.pages.dev/docs/delivery/#offline-maintenance)显式处理；已释放或丢弃的数据无法恢复。
