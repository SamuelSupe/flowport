# 交付与恢复

## 接收与发送

| 阶段或事件 | 行为 |
| --- | --- |
| 校验、单批预算或持久化失败 | 返回失败，不能确认接收成功；无可靠应用级确认的协议另有边界。 |
| 接收成功 | 确认本 Worker 的本地持久接受，不确认下游送达。 |
| 已接收数据解析或 Pipeline 失败 | 记录有界诊断和持久计数，释放输入载荷。 |
| 队列所需的 Lookup 版本缺失或损坏 | 保留队列并暂停相关处理，尝试重新获取资源；不按普通 Pipeline 失败释放载荷。 |
| 某个目标发送失败 | 保留该目标的处理结果并退避重试；其他健康目标继续发送。 |
| 正常未完成队列超容量 | 按原始接收顺序 FIFO 淘汰，允许数据丢失，累计独立丢弃计数。 |
| 进程重启 | 恢复本地未完成队列；远端已接收、本地尚未确认的分支可能重复。 |

每流与 Worker 均有本地队列容量约束；节点还受批次数上限约束。逻辑容量不是磁盘空间上限，日志、检查点、配置历史与空间回收还需磁盘余量。受保护的旧隔离失败载荷不会自动淘汰；无法腾出空间或存储失败时仍可能拒收。

FIFO 依据原始接收顺序，不依据重试时间、扇出完成时间或输出 ID。FIFO 淘汰不代表下游恢复；已经淘汰的数据不会在恢复后重放。未完成分支可能因重试交错，不承诺全局投递顺序、跨目标事务或严格只发送一次。

## 持续故障与恢复

发送目标持续故障只告警，**不暂停新接入**。同一 Worker / 数据流 / 目标连续失败至少 5 次且持续 30 秒触发告警；仍按退避规则重试，容量满后自然 FIFO 滚动。健康目标的成功不能清除其他目标的告警；受影响目标成功确认后恢复。

修改目标地址或凭证后，重新发布相关数据流并等待 Worker 安装。同一目标 ID 的积压使用新安装的已发布连接配置重试，同时保留原处理结果与目标 ID，不重新执行 Pipeline。

运行视图分别显示输入处理失败、目标分支发送失败、FIFO 丢弃及目标告警。分支失败数不等于唯一输入数。摘要脱敏且有界，不默认保存业务原文或完整 HTTP 响应体；没有独立失败记录、查看载荷或人工重放流程。

## Worker 与旧载荷

每个 Worker 使用独立本地持久队列；管理端不转发业务数据，节点之间不复制队列。节点磁盘永久丢失时，其本地未发送数据不能从其他节点恢复。不能把部署多个 Worker 理解为队列副本。

升级前清点旧隔离失败载荷，停止对应进程后按官方运维步骤显式导出或确认清理；它们不会自动重试、FIFO 淘汰或静默删除。历史已释放或已淘汰载荷无法恢复。

## Lookup 与内存状态

批次入队时固定 Lookup 数据版本；连续更新、CDC 分块和重启恢复不会改变该批次使用的版本。已经处理完成的发送积压只重发原结果，不再次执行 Lookup、缓存或聚合。自动更新按各 Worker 的后续批次边界切换，集群可能短暂使用不同版本。

缓存、上下文和未输出的聚合是有界内存，按 Worker、流发布版本与输入类型隔离，重启清空。尚未处理的输入恢复后使用新的空状态；已入队的聚合结果由持久队列恢复。单流配置包不包含这些内存状态、队列、游标或 Lookup 数据，不能替代完整备份。

## 0.2.1：Kafka 历史数据投递

修复 Kafka 将事件时间用于固定 20 秒投递超时判断的问题，历史日志、指标、链路及其他 Point 数据不再因时间较旧而在发送前失败。Kafka 消息时间与编码载荷中的原始事件时间保持不变，适用于全部 Kafka 输出及复用该协议的服务预设。

每次 Kafka 发送由 config.timeout_seconds 控制，默认 20 秒、范围 1–120 秒，并遵守上层更短的取消或截止时间。重试从新一次发送开始计时；发送失败仍保留原队列和处理结果，不通过改写事件时间或清空积压恢复。

0.2.1 沿用控制协议 v6 和检查点格式 3。停止服务并备份完整数据目录、master.key、Lookup 资源与环境配置后升级管理端及全部 Worker。恢复原数据目录后，保留的 Kafka 积压自动重试；已被 FIFO 淘汰的数据无法恢复。目标 Broker 或云服务自身的时间范围与保留策略仍适用。
