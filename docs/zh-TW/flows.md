# 資料流設定與發布

[FlowPorts 0.5.3](../../README.zh-TW.md) · [Docs](../index.md) · [Website](https://flowport.pages.dev/zh-TW/docs/)

未完成草稿可暫缺來源、目標或目標配額；已填配額仍須為正數且合計不超預算。儲存不啟動採集或改變執行版本。發布須補齊目標及全部配額。自動配額在發布時固化，新增目標不會自動重分配手工配額。

發布後使用執行檢視的送達驗證。等待目前版本安裝、來源就緒、最新報告及舊積壓清空，先開始驗證再從上游傳送真實資料。支援的 HTTP 與 DataKit 來源提供可複製範例，須替換為已發布 Token。比較新增接收批次、成功處理批次和各目標確認增量；為各路由傳送匹配樣本，並在下游核對內容。不自動傳送或追蹤單筆記錄；報告過期或連線中斷時無法確認送達。版本、Worker 分配、程序實例或計數變化後須重新驗證，重新整理或切換範圍也會重設。協定確認不代表下游業務處理完成。

> **0.5.0 策略變更：** 以下保留／重試說明均受新通道上限約束，預設 5 次。耗盡自動丟棄未確認資料，至少等待 60 秒後單批試投；歷史次數保留。相關節點須全部升級協定 v8。詳見[投遞策略](https://flowport.pages.dev/zh-TW/docs/delivery/)。


編輯頁和執行檢視頂部顯示資料流 ID 並可複製。已登入管理員可主動檢視、隱藏及複製接入 Token（含 Vector）；草稿和已發布憑證分開顯示，草稿修改須發布並由 Worker 安裝後才生效。執行檢視僅在彙總範圍提供 Token，指定 Worker 時不顯示，避免混淆安裝版本。其他上游憑證維持遮罩。普通查詢和匯出仍脫敏；API Key 和 MCP 不可還原接入 Token。

首次發布前，Overview 提供建立第一條資料流或繼續設定入口。範本先開啟來源設定，保留腳本和樣本。無需轉換時可直接進入傳送目標，需要時再新增可選處理規則。在流內新增並選擇目標後會自動選中，來源設定與腳本保持不變。

使用目前草稿偵錯時，按設定的 measurement（預設 Source 類型）解碼，並附帶執行時的 source_type、collectway_flow Tag。樣本須代表已解碼的來源記錄；預覽不連接上游或投遞資料。

彙總顯示最新發佈設定；選擇 Worker 後顯示該節點已安裝的鏈路。發佈與安裝狀態分開顯示，積壓計數包含歷史版本。

編輯器會標示尚未儲存的修改，儲存或發佈時顯示提交進度。發佈成功後直接進入執行檢視，核對設定狀態、Worker 安裝版本與實際投遞，無需返回列表再次開啟。資料流列表使用「停止接入／恢復接入」按鈕；停止接入僅停止新輸入，積壓繼續處理與傳送，目標故障不會自動停止接入。

編輯器頂部依「儲存草稿 → 發佈資料流 → Worker 安裝」說明生效步驟。儲存只保留修改；發佈後在執行檢視確認實際安裝版本，再以實際投遞確認目標收到資料。修改目標地址或憑證後，儲存結果會直接展開「引用流與設定生效狀態」，可逐條檢查引用流並進入草稿發佈；僅修改目標名稱無需重新發佈。 傳送目標步驟底部提供「儲存並發佈」，檢查後可直接提交，無需返回頁首；儲存或發佈出錯時返回頂部顯示具體錯誤。

資料流包含 Source、各型別 Pipeline、預設目標、可選 Tag 分流、執行位置與佇列容量。發布建立不可變版本並由 Worker 非同步安裝，草稿與執行版分開。儲存前可在實際 Worker 測試連線，與 Pipeline 樣本各自驗證。[診斷](https://flowport.pages.dev/zh-TW/docs/#configure)提供詳細範圍。

## Source 與接入設定

可按名稱、流 ID、Source 型別或顯示名稱搜尋。新建流程可篩選接入方式與訊號。推送需要 Token/監聽器，消費需要佇列/主題與認證，拉取需要完整 URL。

進階 JSON 是完整 Source 物件。容器監聽器通常使用 0.0.0.0 與映射埠。保留 ******** 會沿用同型別既有秘密，輸入新值並發布才替換；更換協定需重新設定。[Source](https://flowport.pages.dev/zh-TW/docs/integrations/)說明支援邊界。

## 處理規則

選擇日誌、指標、追蹤等獨立腳本。空腳本透傳，DataKit 支援 15 類。樣本除錯顯示解碼 Point、輸出、過濾、型別、Tag 與原始 JSON，不會送到下游。輸入/腳本/型別改變後標記舊結果失效。關閉回到編排並保留樣本與結果。詳見 [Pipeline](pipeline.md)。

## 預設目標與組合分流

多個預設目標各自複製、確認與重試，每流最多 32 個不同目標。沒有目標的草稿可存但不能發布。

支援 eq、neq、exists、not_exists 與巢狀 AND/OR。首條命中替換預設集合，未命中使用預設。每條規則各自選擇一或多個目標；永久存檔目標應包含在預設與每條規則中。讀取處理後 Tag，普通欄位需用 set_tag 轉換。名稱/值區分大小寫、不自動裁剪。signals 過濾不會繼續下一條規則。詳見[分流](https://flowport.pages.dev/zh-TW/docs/pipeline/)。

目前失敗處理與遷移: [FlowPort](https://flowport.pages.dev/zh-TW/docs/delivery/).

## 位置與容量

可自動選擇允許 Worker 或指定節點。推送/共享消費可多節點，拉取等使用獨占租約。網路、TLS 檔案與雲端身分必須在執行 Worker 可用。

新流預設每 Worker 256 MiB、500 個內部批次，按輸入和各目標固定分配。節點預設 10 GiB、最多 10000 內部批次；預留及歷史占用須同時容納。物理日誌和檢查點需額外空間。 接收確認僅表示資料已進入本機持久佇列。目的端預設最多重試 5 次（首次不計，可設定 0～100）；耗盡後不可逆丟棄未確認資料，沒有死信載荷或人工重播。輸入區滿時拒收，輸出區滿時僅在該通道內 FIFO 淘汰；縮容保留舊積壓並等待清空。處理失敗也可能釋放輸入。發布成功不代表 Worker 已安裝或下游已收到，須核對下游實際內容。

## 儲存、發布與版本

草稿只儲存編輯；發布驗證並配發新版；停止不再接受新輸入但繼續既有傳送；啟用恢復最後發布版。目標儲存後參照流需再發布才作用於新輸入。

同步中檢查預期/已安裝版、Source 與錯誤，發布成功不等於收集成功。版衝突應重新讀取核對；未儲存離開會確認。

## 從執行圖進入設定

鉛筆可開啟 Source、Pipeline/型別、Tag 規則或相應 Destination。點擊不儲存或發布。圖顯示發布版，編輯器載入最新草稿。返回保留 Worker、動畫、捲動及原按鈕焦點。編輯時只暫停圖的輪詢，實際收集持續；遲到回應不會在離開後重新開啟。腳本清單可鍵盤捲動。

## 停止與刪除

先停止並等待全部關聯 Worker 的最新停止與健康空佇列確認。執行中、積壓、失敗、缺少報告或歷史節點離線不能刪除。傳送失敗在容量內自動重試；舊隔離資料須停機後明確匯出或清理。正常排空移除節點可用最終空確認，強制移除的未知資料不能當空。詳見[叢集](https://flowport.pages.dev/zh-TW/docs/cluster/)與[排障](https://flowport.pages.dev/zh-TW/docs/delivery/)。

目標故障時持續接入。超過流或 Worker 的位元組／批次配額，依原接收順序 FIFO 淘汰正常積壓。不借用轉換配額；單批輸出超限視為處理失敗並釋放輸入。舊隔離載荷仍受保護，須明確停機遷移。

已發布的資料流 ID 在刪除後仍保留為歷史資源識別，不可重新用於新資料流。建立新資料流時使用新 ID，避免繼承 Worker 的游標、租約歷史或計數而跳過初始採集。同一資料流停用後再啟用仍從原持久進度繼續；從未發布的草稿刪除後可重複使用 ID。

草稿使用獨立的 `draft_revision`。新建為0；修改須同時回傳讀取的 `revision` 與 `draft_revision`，儲存成功回傳新的草稿版本。發佈請求本文必須包含儲存回應中的 `draft_revision`；缺少時回傳400，草稿變更時回傳409，不會發佈其他編輯端的新修改。切換 Source 協定時必須重新填寫敏感設定。資料流清單的發佈歷史提供分頁查詢與設定比較，可將歷史版本恢復為草稿；恢復不立即切換執行版本，重新發佈時使用目前傳送目標的地址與憑證。

已移除 Worker 的歷史接收、投遞及目標計數在清單與執行檢視中一致保留，樣本標記離線。強制移除且佇列未知的節點仍阻止刪除資料流；若節點已永久遺失，先停用資料流並從負載平衡與上游移除節點，再於資料流清單處置失聯節點，選取已移除節點並輸入完整資料流ID確認。`POST /flows/{id}/abandon-worker` 使用 `worker` 與等於資料流ID的 `confirm`，僅解除該節點對此流刪除的阻塞；不修改節點磁碟或最後報告，也不略過其他節點的排空檢查。決定會持久保存並記錄強制操作稽核，可由 `GET /flows/{id}/recovery` 查詢。

目前失敗處理與遷移: [FlowPort](https://flowport.pages.dev/zh-TW/docs/delivery/).


自 0.1.19 起，已開始的投遞若在回傳前被 FIFO 淘汰，遲到的失敗或成功仍依實際結果持久計入傳送嘗試／成功點次，並更新目標健康；不恢復載荷、不撤銷淘汰計數、不再次推進游標。同一分支可同時計入 FIFO 淘汰與已確認投遞，兩者不能相減為唯一輸入數。有效連線的遲到成功可解除該目標告警；舊發布連線仍不能更改目前目標健康，已移除且無積壓的目標不因遲到失敗重建告警。

每流保留最近 100 個版本，全部加密快照共用 64 MiB。優先回收最舊未引用歷史；目前、正常／舊隔離佇列、在途發送及管理端批准／Worker 上報的版本受保護，可超過歷史條數。引用快照佔滿預算時新發布失敗，現有接入持續；升級前的超額引用仍保留。刪除已排空流會回收完整歷史，但保留不可複用的身分；只能查詢／恢復仍保留版本。日誌回收稍後釋放實體空間，舊失敗載荷不會靜默刪除。 曾獲分配的遠端 Worker 只在本地正常佇列與舊失敗載荷均清空後回收已刪流配置，離線節點重連後處理。

目前版本使用控制協定 v8、檢查點格式 3，可讀取舊格式 1/2。升級前停止服務並備份各節點完整資料目錄、master.key、Lookup 資源與環境設定，再協調升級管理端和全部 Worker。降級須恢復升級前完整備份並核對後續新增資料；不可用舊程式直接開啟或覆蓋升級後的目錄。

## 場景範本與單流設定匯入匯出

點擊「新建資料流」可選擇空白建立、場景範本或匯入設定。範本涵蓋 HTTP 日誌轉送、依日誌等級分流、60 秒短期去重、錯誤上下文與窗口聚合指標，預填 HTTP JSON 來源、腳本與樣本；來源可更換。填寫憑證，選擇傳送目標與 Worker，在 Pipeline 樣本除錯中驗證，再儲存草稿及發佈。聚合目標須支援 metric；快取與窗口使用有界記憶體，依 Worker、發佈版本與輸入類型隔離，重啟清空。

在資料流列表點擊「匯出設定」，選擇已儲存草稿或最近發佈設定並下載 JSON；未儲存內容不包含在內。檔案使用 `format: "flowport.flow"`、`version: 1`，包含來源設定、各類 Pipeline、預設及分流目標引用、Lookup 綁定、佇列容量與 ACK 策略。不包含共用目標連線、Lookup 內容及同步憑證、執行位置、佇列、採集游標、發佈歷史或記憶體狀態，不能代替完整備份。

Token、密碼、headers、URL、連線字串和私鑰等敏感連線欄位會遞迴移除並列在 `removed_fields`。腳本、SQL 查詢及自訂設定的字面值保持原樣，分享前須檢查。匯入會再次移除敏感欄位，不以 `********` 恢復舊憑證。

匯入步驟：

1. 先在目標工作空間建立傳送目標與 Lookup；Lookup 資料另外上傳或同步。
2. 開啟「新建資料流 → 匯入設定」，選擇最大 2 MiB 的 JSON。系統檢查版本、Source 類型及結構，顯示摘要和移除欄位。
3. 將每個預設／分流目標與 Lookup 引用明確映射到本地資源後繼續。同名或同 ID 不會自動綁定，也不建立或覆寫共用資源。
4. 檢查名稱、連線、認證、Worker、佇列容量與規則。Lookup 自動更新策略與固定版本保持不變；固定版本須存在於所選資源且相容，可在 Pipeline Lookup 面板確認或調整。
5. 測試樣本，儲存新草稿，再明確發佈。選檔或進入編輯器不會儲存、啟動接入或修改原流。新流使用新 ID 並重設發佈和執行狀態，不繼承採集進度；消費類 Source 須重新核對起始位置。

REST：`GET /api/v1/flows/{id}/export?configuration=draft|published` 回傳脫敏設定包，預設 draft；`POST /api/v1/flows/import-preview` 接收整個包並回傳正規化設定及完整依賴清單，不寫入儲存。映射依賴並指定新 Flow ID 後，使用現有草稿 PUT 與發佈 POST。沿用認證及 2 MiB 管理請求限制；匯出需要 read、匯入預檢需要 write，儲存和發佈沿用稽核。MCP 工具為 `exportFlow`、`previewFlowImport`。場景範本在 UI 提供，腳本語義見 [Pipeline 使用](pipeline.md)。


匯入頁會顯示資源對應進度，內容捲動時底部操作按鈕保持可見。檢查檔案時可取消或更換檔案，舊請求的回應不會覆蓋新選擇。Lookup 清單只在本次視窗開啟期間重複使用；載入失敗或資源變更時，點擊「重新整理資源」即可，不必重新上傳檔案，檔案摘要和已選傳送目標會保留。關閉匯出視窗也會取消尚未完成的下載請求。

「發布歷史」比較目前草稿與所選版本的來源、Pipeline、Lookup 綁定、目標、分流、佇列容量和執行位置。還原只替換草稿，檢查並重新發布後才會改變執行設定；也應核對綁定中的固定 Lookup 資料版本。工作階段失效後重新登入不會自動開啟先前的建立對話框。


編輯器保留 ID、Token 與主要操作；展開「儲存與發佈說明」可查看生效步驟。儲存只保留草稿，發佈後須確認 Worker 安裝版本及實際投遞。


目標或分流設定尚未完成時仍可執行樣本腳本。處理結果照常回傳；路由預演獨立提示設定錯誤，補齊後重新執行。發佈仍驗證完整設定。


Pipeline 調試、連線診斷、儲存和發布均使用目前來源設定，包括尚未收起的進階 JSON；無效的進階 JSON 會阻止調試，不會退回舊設定。


發布成功提示表示設定已儲存；Worker 是否完成安裝以執行檢視中的設定狀態為準。

## 固定容量隔離

編輯頁以資料流名稱為標題，並區分未儲存修改、已儲存草稿和執行設定。傳送目標步驟的「通道容量」區域集中展示總預算、已分配量及輸入／輸出配額；各區域按列編輯位元組和批次。超過預算或缺少配額時禁止發布，詳細淘汰和縮容規則可展開查看。

新資料流預設 256 MiB 和 500 批次；已有工作區預設值與明確配額不自動更改。僅支援固定容量隔離。在目的端設定分配 `queue_capacity.input` 和 `queue_capacity.outputs`，儲存並發佈。新發佈若省略配額，將位元組預算和 500 批次均分給輸入與全部目標；編輯器儲存時也寫入初始值。已有明確配額不自動重分配，新增目標須手動分配。單位為 Worker × 資料流 × 目的端。分區合計不超過 `queue_bytes` 與 `queue_capacity.batches`，預留與舊版未遷移積壓合計不得超過節點位元組上限和 10000 批次。多個預設流可能超過節點批次上限，須明確調小配額，系統不會自動縮減。未分配餘額不屬於通道，不互借容量。

升級前在每個 Worker 備份副本執行 `collectway -queue-capacity-preflight -data-dir <Worker備份副本> -queue-bytes <節點位元組預算>`，不要直接操作生產資料目錄。預檢依中繼資料估算，不能驗證載荷完整性或未來調度。舊不可變版本保留原位元組預算，Worker 以預設 500 批次嘗試固定預留；已有預留在重啟和後續升級時保持不變，新增目標須明確分配；缺少的輸出記錄數在鎖外分批讀取並持久保存（每批最多 64 條、約 32 MiB）。容量不足、目標不符或載荷不可讀時保留積壓並暫停新接入；上游緩衝能力依來源而異。重啟前先排空記憶體視窗。協定 v6 與 v8 不相容，須協調升級並可能中斷接入。發佈不代表 Worker 已安裝，停用資料流仍保留預留。

舊積壓超過預設分區配額時，以配額與使用量較大值預留並進入縮容排空。輸入超額時拒收新資料；輸出超額時保留舊積壓，但丟棄並計數該通道的新分支。預檢逐區顯示配額、使用量及實際預留，節點必須有足夠容量。仍啟用的流移出 Worker 後，須等本地積壓、在途請求與記憶體視窗全部結束才釋放預留；重新分配時重新申請。整體停用的流仍保留預留。 管理端及該 Worker 均須包含此修復；舊版 v8 Worker 會忽略釋放指令。準備逾時只在載荷讀取之間檢查，單次磁碟讀取或持久提交可能超過該時間。

輸入區滿時拒收新資料，不淘汰輸出。HTTP/gRPC 回傳可重試錯誤，可確認來源保留未確認資料，UDP 計數丟棄。DataKit、Firehose 與 CDC 整請求／交易仍原子入隊。游標中繼資料不足時拒收，不刪除舊收據的全部分支。

同一 WAL 交易移除輸入、加入輸出並依各通道原始接收順序淘汰。拆批、多目標副本、重試、退避和在途批次皆占配額。單一超大分支只丟棄自身；在途資料受保護，無法釋出空間時丟棄新分支。容量丟棄不消耗傳送次數、不計成功，記錄數預存於中繼資料。全部分支終結後才依序推進游標，CDC 仍可能有資料缺口。

縮容保留舊積壓，超出新值時顯示「縮容排空」，新輸出按滿容量處理；舊占用排空後才釋出預算。刪除目標顯示「退出中」，舊輸入、輸出和在途請求結束前保留預留。新增目標需明確分配，增容或遷移預檢失敗保留原安裝版本。不再提供共享容量模式。

執行詳情逐 Worker 顯示版本、用量、配額、實際預留、最老時間及容量丟棄。容量狀態獨立於投遞健康；「持續淘汰」代表最近 5 分鐘有容量丟棄，傳送成功不會立即清除。離線和過期報告標示最後狀態。控制協定 v8 要求管理端與相關 Worker 全部升級，管理端發佈不代表 Worker 已安裝。

僅隔離邏輯容量和淘汰範圍，磁碟、CPU、網路及 Store 寫入仍共享，實體磁碟不足可能停止全節點接入。重啟保留配額、順序、重試與計數。

容量生效比較依區域與配額值判斷，不受 JSON 欄位順序影響；執行值使用目標名稱展示。退出中的通道繼續顯示其保留配額。
