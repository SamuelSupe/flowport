# Lookup 資料擴充

[FlowPort 0.2.0](../../README.zh-TW.md) · [使用指南](https://flowport.pages.dev/zh-TW/docs/pipeline/)

Lookup 提供可管理、可同步、可版本化的本機查詢。管理端取得完整快照並驗證，Worker 下載不可變檔案，不保存外部來源憑證；事件處理時不連接遠端服務。維持單一執行檔，不新增資料庫或排程服務。

以下畫面於 2026-10-20 使用隔離實例與合成資料，從 0.2.0 候選構建的英文介面拍攝。所示介面已包含於 0.2.0，截圖清單保留原始拍攝構建資訊。地址及數值僅為範例，可點選圖片放大。

## 建立與使用

在 Lookup 頁建立資源，選擇上傳、HTTP(S)、S3 相容儲存、PostgreSQL 或 MySQL。上傳 UTF-8 CSV、CSV.GZ 或自行提供的 MMDB。CSV 欄名必須唯一且非空，內容以字串處理。資源頁顯示試查、同步狀態、版本、引用資料流及 Worker 實際版本。

在 Pipeline 面板新增繫結，選擇自動更新或固定版本，明確指定 Field/Tag 輸入、查詢欄及輸出對應。插入函式後可移至指令碼所需位置。名稱必須是字串常數，函式執行同一繫結並回傳是否符合。正常儲存草稿再發佈。

在左側搜尋並選取資源。「資源設定」只顯示目前來源需要的欄位，驗證、TLS 及進階參數預設收合；「試查」選擇查詢欄位並輸入值，以表格查看結果和實際版本；「版本與狀態」集中查看歷史版本、Worker 安裝情況與引用資料流。同步頻率可選常用週期或自訂。離開時會提示尚未儲存的修改，儲存後才能上傳、同步或回復版本。

編輯長表單時，儲存操作列會保持可見。新增資源後會標示下一步上傳或同步；上傳成功或首次手動同步後，自動進入試查。已儲存連線位址中的星號代表保留原值。驗證請求標頭接受空物件或值全部為字串的 JSON 物件。

### 7. 發佈並更新查詢資料

核對樣本後，確認來源和發送目標已設定，點擊「保存草稿 → 發佈數據流」，並在執行檢視確認 Worker 已安裝設定。樣本調試不發送資料；實際投遞仍需檢查目標收據。

例如，將 CSV 中 `payment` 的團隊改為 `交易平台组`，重新上傳完整 CSV：

- 繫結選擇「自動更新」時，Worker 安裝新資料後，新接收的批次使用新版本，無需重新發佈資料流；Worker 之間允許短暫版本差異。
- 已入列的舊批次繼續使用接收時固定的版本，結果不會隨查詢表更新而改變。
- 繫結選擇「固定版本」時，繼續使用指定版本；修改版本選擇並重新發佈後才切換。

「自動更新」決定繫結跟隨哪個資料版本；資源的「自動同步」決定何時從外部來源取得資料。檔案上傳 / API 不會監視電腦上 `services.csv` 的變化，需重新上傳。若需要定時重新整理，可將資源來源改為 HTTP(S)、S3、PostgreSQL 或 MySQL，保留欄位結構並啟用「自動同步」；Pipeline 繫結和指令碼可沿用。同步失敗會繼續使用最後有效版本。

## 四種比對

Exact 支援最多四個複合鍵，預設區分大小寫，可明確忽略大小寫。重複查詢鍵使索引無效。整數保留十進位文字，不將浮點輸入隱式轉換為鍵；請明確使用既有轉換函式。

CIDR 支援 IPv4/IPv6，預設最長前綴，也可選首筆或全部；相同前綴依資料表順序。Regex 使用預先編譯的 Go RE2，依表順序取首筆或全部，不支援環視、反向參照或「最具體正規表示式」。MMDB 依資料庫最長前綴查詢 IP，提供國家、地區、城市、ASN、組織預設及自訂路徑，例如 `subdivisions.0.names.en`。資料庫由使用者提供。

## 同步與完整性

預設每 15 分鐘檢查，可設 60–86400 秒，亦可立即同步。同一資源不並行，管理端最多兩個工作，每次總時限 60 秒；失敗於下一週期重試。HTTP 支援驗證標頭、TLS、ETag/Last-Modified，不跟隨重新導向。S3 只讀指定 Bucket/Key，可選物件版本，不掃描整個儲存桶。

SQL 使用唯讀帳號及唯讀 Repeatable Read 交易，執行一條不含分號的 SELECT，不分頁、不做 CDC、不拼接查詢。整數與精確數值保留文字精度。SQL CIDR/Regex 資料表必須指定唯一、非空、整數型別的順序欄，完整讀取後排序。中斷、部分讀取及超限使整個候選失效。資料庫帳號權限亦須限制函式行為。

流程為完整取得、結構及執行中繫結相容性校驗、建立索引、持久化、分發、Worker 安裝。相同內容不新增版本，但成功檢查仍更新新鮮度。空資料表預設拒絕，可明確允許。缺欄、重複 Exact 鍵、無效索引或容量不足均保留最後有效版本。超過兩個週期未成功檢查顯示過期警告，不停止本機查詢。

## 批次與版本

資料流設定版本、Lookup 資料版本及批次實際版本分開記錄。自動更新不重新發佈；各 Worker 驗證後在下一批次入列交易固定版本。叢集可有短暫版本差異，上游不能指定這些版本。

同一批次、CDC 分塊及當機恢復都用接收時固定的版本。已處理的發送積壓重送原結果。固定版本透過正常發佈生效。啟用歷史版本會暫停自動同步，恢復時須在「資源設定」重新啟用「自動同步」並儲存。

首次無有效版本時拒絕發佈或啟用。佇列所需版本遺失或損壞時暫停相關處理並重新取得，保留載荷；資源不可用既非未符合，也非可釋放輸入的 Pipeline 失敗。管理失聯時沿用完整本機版本，非獨佔延續與獨佔任務租約仍依原規則。

## 容量、安全與升級

初始上限：CSV/SQL 32 MiB、100000 筆、64 欄；Regex 1000 條、每模式 2 KiB、每輸入 64 KiB；MMDB 128 MiB；每行程候選、載入及索引預算 256 MiB；每節點檔案 1 GiB。這是保護值而非容量承諾，解壓、建構、並行同步及被引用舊版本都計入，可能在達檔案上限前拒絕更新。Pipeline 維持既有執行時間預算。

目前、固定、佇列、執行中及已授予 Worker 的版本均受保護，保留最近五個無引用成功歷史版本，不淘汰業務佇列來騰空間。中繼資料讀取使用 read，內容、試查與修改需 write；憑證回傳 ********，稽核不含完整內容或秘密。檔案另有串流上傳限額，一般管理請求仍 2 MiB。MCP 管理、同步、試查及讀狀態，檔案傳輸走 REST。

資源獨立加密保存在 native/lookups/，設定與佇列只存引用。控制協定 **v6**、檢查點 **格式 3**，管理端與所有 Worker 必須協調升級，舊程式拒絕新格式。停機後備份各節點完整資料目錄、master.key 及資源檔。降級必須恢復升級前完整備份，不可只替換執行檔。


Lookup 自動同步以 `system` 操作者寫入稽核。Worker 狀態包含自動更新使用的版本，以及固定綁定與佇列的已安裝版本。欄位映射沿用既有 32 MiB 批次輸出限制；過大的映射會在配置輸出記憶體前拒絕。


Point 鍵名唯一；輸出名稱不可重複，包含 Field/Tag 之間。僅補缺失保留同名的既有欄位或 Tag；覆寫時依目標類型寫入。MySQL 一致快照要求 InnoDB 等支援交易快照的資料表。
