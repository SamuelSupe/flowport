# Pipeline の使用

[FlowPorts 0.5.3](../../README.ja.md) · [Docs](../index.md) · [Website](https://flowport.pages.dev/ja/docs/)

GuanceCloud Platypus の Go 実行器を使い、Vector VRL ではありません。ソース、キャンバス、ショートカットは同じ種類別スクリプトを編集し、.ppl を入出力します。読み込み失敗は下書きを保持して再試行できます。作業領域は 600px 以上、全高は 720px 以上で高い画面では表示高の 80% に拡張し、各パネルが独立スクロールします。

1 レコードの実時間予算は 100ms のままです。受理済み入力バッチの実行は最大 3 回です。最初の 2 回は入力を保持して候補状態を戻し、1 秒、2 秒待機します。3 回目も超過した場合はそのバッチを pipeline_error として解放し、失敗と破棄バイトを記録します。回数は再起動後も残り、投入時の版と FIFO に従います。Worker 共通の容量・スコープ数不足は入力を保持して再試行し、スコープ単体の 8 MiB 超過、解析、型、出力エラーは入力を解放します。

## 編集とサンプル

1. Pipeline で信号種類を選択します。
2. ソース編集または関数・代入・条件・ループの追加を行います。各表示は同期します。
3. サンプル調整を開きます。閉じる/Escape で入力・結果を保持して元に戻ります。実行中の閉鎖はブラウザ待機を中止しますが、開始済みサーバー実行の停止は保証しません。
4. JSON オブジェクト/配列を入力し、必要なら整形して実行または Command/Ctrl+Enter を押します。最大 100 件、下流へは送信しません。
5. 前後、出力/除外数、計測名、Tag、型、ナノ秒時刻を確認します。複数出力や子 Point 種類を切り替え、単入力/単出力では追加・変更・削除と旧値を確認します。
6. 閉じて修正、再実行して保存/公開します。

処理前はデコード済み Point で原始 JSON ではありません。原始 JSON コピーは before/results を精度保持で返します。フィールドは 50 件/ページ。除外は実行器報告を使い単純な入出力差ではありません。複数結果を位置で対応づけず、所要時間にはネットワークを含みます。

HTTP の json/ndjson/text は受信形式で、サンプルは JSON です。大整数とナノ秒の文字表現を保持します。整形とバックエンドの JSON デコードはどちらも最大 64 層です。変更後の旧結果は古いと表示し、解析/実行失敗は修正して再試行できます。

## 入出力と公開検証

.ppl 導入後に種類とサンプルを確認します。書き出しはソースの保存で、接続情報やフロー全体のバックアップではありません。グラフは構文、最終実行可能性は Go 側が検証します。不正構文や非対応関数は公開できません。タイムアウト、無限ループ、解析失敗は元バッチを保管した失敗になります。

現在の失敗処理と移行: [FlowPort](https://flowport.pages.dev/ja/docs/delivery/).

## バージョンと失敗時の解放

受信確認はローカルの永続キューへの保存だけを示します。送信先ごとの再試行は初回を除き既定 5 回（0～100 回で設定可）です。上限到達後は未確認データを不可逆に破棄し、デッドレターや手動再送はありません。入力領域が満杯なら新規受信を拒否し、出力領域が満杯ならそのチャネル内だけで FIFO 破棄します。縮小時は既存の滞留を保持して解消を待ちます。処理失敗でも入力を解放する場合があります。公開成功だけでは Worker への適用や下流の受信を証明できません。下流の内容を確認してください。

再試行では処理結果、宛先 ID、配信識別子を保持します。同じ宛先 ID を再公開すると、次の送信試行で新しい接続設定を使い、Pipeline やルーティングは再実行しません。新しい公開版から宛先を削除した場合、その分岐は元の接続を保持し、別の宛先へ送信しません。件数は元の入力バージョンに属し、宛先の保存や下書きの編集だけでは変更されません。

processing_failed_batches は入力失敗、互換名 sending_failed_batches は再試行を含む送信失敗回数です。送信失敗率は失敗回数を失敗回数と sent_batches の合計で割ります。overflow_dropped_batches と overflow_dropped_bytes は入力または出力分岐の FIFO 破棄、discarded_bytes は処理失敗と FIFO 破棄を計数し、送信失敗で保持するだけでは増えません。受信、破棄、件数、順序付き確認を同じ永続トランザクションで更新します。保存失敗では旧データを保持し、新規受信を確認しません。再試行は確認を完了しません。開始済みリクエストは撤回できず、破棄した分岐も宛先に届く場合がありますが、キューには復帰しません。タイムアウトやクラッシュによる重複は残ります。

## Lookup

Lookup はローカルの不変データを使い、バッチごとに版を固定します。リソース不可用でもキューを保持します。[Lookup](lookup.md) を現在の制御プロトコル v8、チェックポイント形式 3 への協調更新と、ダウングレード時の更新前完全バックアップが必要です。


## キャッシュとウィンドウ

Pipeline の「キャッシュとウィンドウ」で例を選んで挿入し、フィールド名を調整して実行します。`cache_get`、`cache_set`、`point_window`、`window_hit`、`agg_create`、`agg_metric` を `lookup()`、条件、ルーティングと組み合わせられます。

上限付きメモリは **Worker × フローの公開バージョン × 入力データ型** ごとに分離され、同じ範囲内でバッチ間共有されます。再起動や Worker 移動で消去されます。全体での重複排除、Worker 間集計、厳密な一度限りの処理は保証しません。再公開は新しい状態を使い、旧版は受信済み入力の処理後に最後の未完了集計を出力します。停止も同様です。1 時間入力処理に成功しなかった範囲は残りの集計を出力して解放し、未ヒットのコンテキストは破棄します。フロー削除でもメモリを消去します。

プレビューは毎回独立した新規状態を使用し、最後に未完了集計を出力します（`stateful_preview=true`）。稼働中の状態にはアクセスしません。時間間隔、バッチ間状態、再起動は公開済みフローと実際の送信先で検証してください。

### ウィンドウでメトリクス集計

`agg_create(bucket, on_interval="60s", on_count=0, keep_value=false, const_tags=nil, category="M")` はバケットを定義し、時間または件数で出力します。`"0s"` は時間、`0` は件数のトリガーを無効にしますが、両方は無効にできません。`agg_metric()` の呼び出し数によらず、寄与したレコードはバケットごとに 1 回数えます。件数はグループ単位ではなくバケット全体です。イベント時間ではなく Worker 処理時間を使います。アイドル時も約 300ms ごとに確認し、負荷により遅延します。

`agg_metric(bucket, new_field, agg_fn, agg_by, agg_field, category="M")` は `sum/avg/min/max/set` に対応し、`set` は最後の値です。グループのフィールドまたは Tag は文字列、集計入力は数値が必要です。文字列は明示変換してください。float64 計算のため大整数や厳密な小数の精度は保証しません。バケット名が測定名、グループ値が Tag になります。`"M"` または `"metric"` でメトリクスを出力し、`const_tags` で固定文字列 Tag を付加します。元のレコードは明示的な `drop()` がなければ残ります。

### 容量と失敗時の動作

| 項目 | 上限 |
|---|---|
| 状態予算 | 範囲ごとに 8 MiB、Worker の確定済み状態 64 MiB、128 範囲 |
| キャッシュ | 4,096 キー、キー 1–1,024 バイト、値 64 KiB、TTL 1–3,600 秒（既定 100） |
| コンテキスト | 256 グループ、before/after 各 0–128（両方 0 は不可）、1–8 キー、キー 1 KiB・値 4 KiB |
| 集計 | 16 バケット、各 4,096 グループ、各 64 フィールド、1–8 グループキー、キーと出力名 256 バイト・グループ値 4 KiB |
| トリガー | 1 秒–1 時間、1–1,000,000 件、バケット名 256 バイト |
| 固定 Tag | 32 項目、キー 256 バイト・値 4 KiB |

予算は文字列、Point、索引コストの見積りであり RSS 上限ではありません。最大 8 並列バッチの候補状態、デコード、出力も一時メモリを使います。不正な引数、キー欠落、型違い、スコープ単体の 8 MiB 超過は入力を解放します。Worker 共通の容量またはスコープ数不足では入力を保持し、回収後に再試行します。

全 CDC チャンクを含むバッチ全体の結果がキューに保存された後にだけ状態を確定します。途中失敗は部分変更を残しません。タイマー出力の保存失敗はウィンドウを保持し、再試行まで Worker エラーを表示します。保存済み出力は通常の永続キューで再送され、再起動から復元でき、再集計されません。メモリ内のキャッシュ、コンテキスト、集計はバックアップされず、再起動で失われます。受信済み未処理入力は空の状態で再開するため、無停止時と結果が異なる場合があります。

Worker のドレインやフロー削除は、実行中の処理と最終集計の配信完了を待ちます。最終ウィンドウをキューに保存できなければ、永続キューが空でもドレイン完了や削除を許可せず、ウィンドウを保持して再試行します。プロセス終了はメモリ状態を消去するため、停止前のオンラインドレインの代わりにはなりません。

受理済み SQL CDC 入力は有界チャンクでデコードし、その入力全体が成功してから原子的に置き換えます。32 MiB を超える PostgreSQL/MySQL トランザクションは複数の入力からなり、Pipeline は入力ごとに確定し、共通の引継ぎ確認は全入力の完了を待ちます。

異なるフロー、公開リビジョン、データ種別の状態スコープは、別スコープがディスクへコミットしている間も処理できます。各スコープは順序を維持し、キューへのコミット成功後に候補状態が有効になります。並行した増加は Worker の共有予算を先に予約し、失敗時に解放します。スコープ単位 8 MiB、Worker 合計 64 MiB と、揮発性状態および停止前の明示的オンライン排出の制約は変わりません。


## 受信・再試行・リソース境界

コンテキスト窓はグループごとの最終入力から1時間で回収され、他グループの通信では延長されません。keep_value も1時間の無入力後に回収します。未出力値は通常の永続出力を通して部分集約を出力してから解放し、件数のみの桶が閾値未満でも同じです。次の同一キーは新規累計です。256窓・桶ごと4096グループと既存メモリ予算は維持します。変更した集約だけコピーし、取消や永続化失敗では候補状態を公開しません。コンパイルキャッシュは個別に退避します。


Pipeline のデバッグ、接続診断、保存、公開は、開いたままの詳細 JSON を含む現在のソース設定を使用します。詳細 JSON が無効な場合は、以前の設定を使わずデバッグを停止します。


通常の Pipeline 出力と定期・最終集計ウィンドウは、宛先ごとにバイト数とバッチ数の割当内で独立して準備します。過大な分岐や同一チャネルの古い出力の容量処理で、空きのある他チャネルが失敗することはありません。単一の過大分岐は既存の滞留を削除しません。残す出力、容量破棄カウンター、入力完了、カーソル受領確認を一つの WAL トランザクションで保存します。送信中のデータは保護されます。準備中に割当が変更された場合は再準備し、書込み失敗時は入力やウィンドウを保持してカウンターやカーソルを進めません。

容量予約が未導入の旧入力には、従来の出力準備全体の予算を適用します。超過した入力は `pipeline/output_limit` で終了し、処理失敗を永続化して受領確認を順番に完了します。ストレージ障害として無限に再試行しません。分離割当が導入済みの場合、過大な分岐はそのチャネル内だけで破棄・計数します。準備中の割当変更では入力やウィンドウを保持して再準備し、デバッグログのみを記録します。実際のストレージ障害では引き続きデータを保持してエラーを報告します。

割当縮小後の排出中ではないチャネルで出力の先頭部分を切り捨てた場合、FIFO 順序がさらに古く、送信中ではない滞留も削除します。定期・最終ウィンドウは既存の滞留より後なので、残すウィンドウ末尾と一部の旧データが割当に収まる場合でも、それより前の削除可能な滞留をすべて終了します。最新の FIFO 末尾を残すための規則です。単一の過大分岐はこの境界を進めず、旧滞留を削除しません。送信中の分岐は常に保護し、容量を占めている場合は同チャネルの新規分岐だけを破棄します。空きのある他の宛先は妨げません。

Pipeline のプレビューと公開ではコンパイルエラーの行・列を保持します。未定義関数、引数数の不一致、型の不一致を識別できる場合は安全な理由も返します（`pipeline_compile_error_reason` と原因コード）。その他は `pipeline_compile_error`、位置がない場合は `pipeline_compile_failed` です。実行エラーは `pipeline_runtime_error`、位置がない場合は `pipeline_runtime_failed` です。位置は `params[0]` と `params[1]`、理由は `causes` に含まれます。画面は各階層を翻訳し、プレーンテキストにも安全な説明を含めます。スクリプトのリテラル、入力値、外部ライブラリの生エラーは公開しません。
