# 数据流配置与发布

[FlowPort 0.2.0](../../README.zh-CN.md) · [使用指南](https://flowport.pages.dev/docs/pipeline/)

汇总显示最新发布配置；选择 Worker 后显示该节点已安装的链路。发布与安装状态分别显示，积压计数包含历史版本。

编辑器会标明未保存修改，保存或发布时显示提交进度。发布成功后直接进入运行视图，核对配置状态、Worker 安装版本和实际投递，无需返回列表再次打开。数据流列表使用「停止接入／恢复接入」按钮；停止接入仅停止新输入，积压继续处理与发送，目标故障不会自动停止接入。

编辑器顶部按「保存草稿 → 发布数据流 → Worker 安装」说明生效步骤。保存只保留修改；发布后在运行视图确认实际安装版本，再用实际投递确认目标收到数据。修改目标地址或凭证后，保存结果会直接展开「引用流与配置生效状态」，可逐条检查引用流并进入草稿发布；仅修改目标名称无需重新发布。 发送目标步骤底部提供「保存并发布」，检查后可直接提交，无需返回页首；保存或发布出错时返回顶部显示具体错误。

接入配置与发送目标参数页提供独立「测试连接」及认证模板，Source 另可「上游试采样」。直接验证当前表单，保存前也能运行；Pipeline 样本调试只验证脚本。集群需选择实际执行节点。详细范围见 [连接诊断与认证](https://flowport.pages.dev/docs/integrations/)。

一条数据流包含来源、各类数据的 Pipeline、默认发送目标、可选 Tag 分流、运行位置和队列容量。每次发布生成不可变版本，Worker 异步安装；草稿与正在运行的版本分开保存。

## 选择来源与接入配置

流列表支持按名称、流 ID、Source 类型 ID 或服务显示名称搜索，例如 `HTTP Server`；编辑按钮直接进入草稿配置。手机表格可左右滑动，键盘聚焦列表后可用左右方向键查看剩余列与操作。

列表中的长名称会省略显示，鼠标悬停可查看完整名称；发送目标包括默认及分流规则引用的全部目标，去重后逐行展示，长目标名同样提供完整名称提示。切换主页面或配置步骤后返回顶部，便于查看当前步骤和操作按钮。

从「数据流 → 新建数据流 → 空白创建 → 选择来源」搜索并选择协议，可结合接入方式筛选，卡片展示支持的数据类型。来源目录已合入创建流程，协议说明仍可在帮助中查阅。必填项带星号。推送类使用独立 Token 或网络监听地址；消费类需要队列/主题及凭证；拉取类需要远端 URL。

高级 JSON 编辑的是完整 Source 配置。补充认证、headers 和 TLS 等选项后，先完成有效的 JSON 对象再收起；数组、未完成的 JSON 或错误字段不能直接保存。容器中的监听器通常填写 `0.0.0.0:端口`，并映射相应端口。

已保存的敏感字段显示 `********`。保留占位符沿用原值；想更换凭证时输入新值，发布后才对新输入生效。更换协议类型需要重新配置连接与认证。

完整必填项、协议上限和可靠性见 [Source 配置与范围](https://flowport.pages.dev/docs/integrations/)。

## 配置处理规则

进入 Pipeline 步骤，选择日志、指标、链路等数据类型，各类脚本独立保存。空脚本透传。DataKit 支持全部 15 类 Point 的脚本。

用具有代表性的样本测试解析、字段类型、过滤和 Tag，确保分流所需值最终是 Tag。点击「样本调试」打开独立工作台，提供输入格式化、处理前后查看、单点字段变化、多点切换和原始 JSON 复制；关闭后回到编排，样本与结果保留。输入、脚本或类型变化后，上次结果会标记为已过期，需要重新运行样本；调试不会将样本发送到 Destination。详见 [Pipeline 使用](pipeline.md)。

## 默认目标与组合分流

发送目标步骤可以选择多个默认目标；同一数据点复制到这些目标，各分支独立确认或失败保留重试。每条流最多引用 32 个不同目标。没有目标的草稿可暂存，但不能发布。

开启按 Tag 分流后，按顺序配置规则。支持等于、不等于、存在、不存在，以及嵌套 AND/OR 条件组。第一条命中的规则替换默认目标集合；未命中任何规则时使用默认目标。希望始终存档的目标应同时出现在默认集合和每条规则中。

每条规则的「命中后发送到」独立选择一个或多个 Destination，顶部显示已绑定目标摘要。比如生产条件绑定生产 Dataway，测试条件绑定测试 Dataway，其他数据使用默认存档目标；选择多个目标会同时复制投递。地址与凭证在「发送目标」实例中维护，修改绑定后重新发布才生效。

`env=prod AND region=cn` 要求两个最终 Tag 同时满足；`(env=prod AND region=cn) OR tenant=vip` 则满足任一分组即可。同名普通字段不参与 Tag 匹配，需先使用 `set_tag`。详见 [规则语义与示例](https://flowport.pages.dev/docs/pipeline/)。

Destination 的 `signals` 可过滤输出类型。它不会把数据转交下一条规则，应确保每种需要保留的数据至少有一个能够接收的目标。

## 运行位置和容量

默认由管理端自动选择允许的 Worker，也可以限制运行节点。推送/共享消费可多节点执行；主动拉取和部分订阅由独占租约选出一个 Worker。同一配置引用的证书路径、云身份和网络连接必须在实际运行节点可用。

流容量是每个 Worker 上该流的字节配额；目标副本和受保护旧失败载荷计入容量。Worker 最多 10000 个本地队列批次，输入和扇出共用严格上限，不借用转换空间；普通积压超容量按原始接收顺序 FIFO 淘汰。单批输出超过准备上限按处理失败释放。新流默认 1024 MiB，可在工作台调整；容量变更须发布，缩小容量也会淘汰普通积压，不改写原处理结果。旧载荷保护和存储失败仍可拒收；物理日志与检查点需额外余量。详见[容量与恢复](https://flowport.pages.dev/docs/delivery/)。

## 保存、发布与版本

| 操作 | 结果 |
| --- | --- |
| 保存草稿 | 保留编辑内容，运行版本和采集状态不变 |
| 发布数据流 | 校验来源、Pipeline、目标和规则，生成新版本并异步下发 |
| 停止接入 | 停止新输入，已接受数据继续按原版本发送 |
| 恢复接入 | 恢复最后发布版本；未发布草稿不能启用 |
| 修改发送目标实例 | 保存新参数；引用它的流重新发布后，新输入及同目标 ID 积压的后续连接采用新配置 |

看到「同步中」时，在运行页或 Workers 详情检查期望版本、实际版本、来源状态和错误。网络失败会持续重试；不要仅凭发布成功判断已经采集。

若保存提示版本冲突，已有其他修改被发布，应重新获取配置并核对后再编辑。离开未保存的流时会提示确认；保存期间防止重复操作。

## 从运行图进入配置

已发布数据流的运行图提供铅笔图标：Source 卡片直达接入配置，Pipeline 卡片进入处理规则，脚本行直接选中对应数据类型，Tag 分流行定位到规则区；每张 Destination 卡片打开该目标的参数弹窗。图标支持键盘操作，悬停显示说明。

进入配置时读取最新草稿或目标参数，运行图仍显示已发布版本。点击图标不会保存或发布；返回或取消后回到运行图，未保存的数据流修改仍需确认放弃。目标参数保存后，相关数据流须重新发布才会采用新配置。

从运行图进入数据流配置后，所选 Worker、动画暂停状态及浏览位置会保留；返回时恢复到原图标，便于继续检查同一链路。配置期间暂停该运行图的自动采样，返回后重新采样，不会停止 Worker 的实际采集或投递。离开运行图后，迟到的配置响应不会再自动打开编辑器或目标弹窗。

脚本较多时列表可滚动，键盘聚焦列表后可用方向键浏览；脚本名称、目标角色和配置图标提供完整提示。手机端使用更大的图标点击区域，截断的名称不影响对应配置的定位。

## 停用与删除

已发布的数据流 ID 在删除后仍保留为历史资源标识，不可重新用于新数据流；新建时使用新 ID。这样避免继承原 Worker 的采集游标、任务租约或计数而跳过初始采集。停用再启用同一条流仍从原持久进度继续；没有发布过的草稿不占用历史 ID。

先停用，再等关联 Worker 确认停止并排空。启用中的流不能删除；离线、存储不健康、缺失队列报告、仍有积压或旧失败载荷时也不能删除。最新下发后必须有新的停止报告，即使只是再次启用同一版本。

解析或处理失败释放输入；发送失败保留目标分支并退避重试，超过容量按原接收顺序 FIFO 淘汰。运行页分别展示失败尝试、淘汰计数与脱敏摘要。旧失败载荷仍阻止排空/删除，须在原 Worker 停机后显式迁移；见[旧载荷迁移](https://flowport.pages.dev/docs/delivery/)。

草稿使用独立的 `draft_revision`。新建为0；修改须同时回传读取的 `revision` 与 `draft_revision`，保存成功返回新的草稿版本。发布请求体必须包含保存响应中的 `draft_revision`；缺失返回400，草稿变化返回409，不会发布其他编辑端的新修改。切换 Source 协议时必须重新填写敏感配置。数据流列表的「发布历史」提供分页查询和配置对比，可将历史版本恢复为草稿；恢复不立即切换运行版本，重新发布时使用当前发送目标的地址与凭证。

已移除 Worker 的历史接收、投递及目标计数在列表和运行视图中一致保留，样本标记离线。强制移除且队列未知的节点仍阻止删除流；若该节点已永久丢失，先停用流并从负载均衡与上游摘除节点，再在数据流列表「处置失联节点」中选择已移除节点并输入完整流ID确认。`POST /flows/{id}/abandon-worker` 使用 `worker` 与等于流ID的 `confirm`，只解除该节点对此流删除的阻塞；不修改节点磁盘或最后报告，也不绕过其他节点的排空检查。决定持久化并记录强制操作审计，可由 `GET /flows/{id}/recovery` 查询。

从 0.1.19 起，已经开始的投递若在返回前被 FIFO 淘汰，迟到的失败或成功仍按实际结果持久计入发送尝试／成功点次，并更新目标健康；不恢复载荷、不撤销淘汰计数、不再次推进游标。同一分支可同时计入 FIFO 淘汰与已确认投递，二者不能相减为唯一输入数。有效连接的迟到成功可以解除该目标告警；旧发布连接仍不能更改当前目标健康，已移除且无积压的目标不因迟到失败重建告警。


## 0.1.21 运行与操作闭环

发送失败仍在原 Worker 本地队列保留并退避重试，持续故障不停止接入，超过容量按原接收顺序 FIFO 淘汰。同一目标 ID 的积压保留原处理结果，Worker 安装新发布版本后，后续发送使用新连接；安装前可能使用缓存连接，在途旧请求无法撤回。解析／Pipeline 失败仍释放输入；旧隔离失败载荷须显式停机迁移。

在已保存目标的参数页展开「引用流与配置生效状态」，查询草稿引用、运行版本是否待重新发布、各 Worker 安装版本、当前连接是否已安装及该目标分支积压。比较的是已保存配置，未保存表单不参与；只改名称无需重新发布连接。可逐条打开流草稿检查并发布，不自动覆盖草稿或批量发布。离线、过期及不健康报告明确标记；安装当前连接不代表在途旧请求已经结束。

Pipeline 调试及发送目标步骤的「样本与路由预演」共用当前样本，运行处理后可切换「路由预演」，查看每个输出点的首条命中规则／默认目标、选中目标、signals 筛选跳过、目标缺失和协议类型不支持。复用运行时 Tag 匹配与类型筛选，最多展示 100 个输出点；不连接目标、不发送样本、不保存或发布。被 signals 排除后不继续匹配下一规则；协议不支持的选中分支在实际运行中仍保留重试。修改脚本、路由、目标或样本后结果过期。

运行页按 Worker 展示最老／最新在队批次的原始接收时间、最老积压年龄，以及当前和前四个分钟桶的 FIFO 丢弃批次及字节。最多持久保留六个分钟桶，从 0.1.21 开始记录，不回填升级前历史；离线节点显示最后报告的时间窗口。批次可能是输入或目标分支，不能换算为唯一输入损失率，也不预测未来保留时间。Workers 页同时展示节点批次数上限和数据目录所在文件系统的可用／总空间；磁盘值包含同一文件系统其他用途，不是 FlowPort 专用空间或预留。旧 Worker 缺失字段显示未知。

## 0.1.23 资源与历史保留边界

历史配置默认每流保留最近 100 个版本，全部加密版本快照共用 64 MiB 预算。按最早版本回收未引用历史；当前版本、待处理/发送队列、旧隔离失败载荷、在途发送及管理端已批准/Worker 上报的版本均受保护，可能超过历史条数。被引用快照占满预算时，新发布失败，现有接入与队列不受影响；升级前已有的超额引用继续保留。删除且排空的数据流回收完整历史；管理端通知曾获分配的远端 Worker，节点仅在本地普通队列和旧失败载荷均清空后回收，离线节点在重连后处理。保留最小身份记录防止旧 ID 复用；历史查询及恢复只覆盖仍保留的版本。逻辑释放后由正常检查点与日志回收释放物理空间，不静默删除旧失败载荷。

升级前停止服务并备份完整数据目录、master.key 和环境配置。0.1.23 可读取旧格式 1，后续检查点写入格式 2，以保护版本回收后的身份约束；0.1.23 使用控制协议 v4；当前开发版为 v5，须协调升级管理端与全部 Worker。写入格式 2 后，旧程序会拒绝打开该目录。回退须恢复升级前的完整备份，并核对升级后新增接收的数据，不能用旧程序直接打开或覆盖新目录。

## 场景模板与单流配置导入导出

点击「新建数据流」可选择空白创建、场景模板或导入配置。场景模板提供 HTTP 日志转发、按日志级别分流、60 秒短期去重、错误上下文和窗口聚合指标。每个模板预填 HTTP JSON 来源、处理脚本与样本；来源可更换。填写接入凭证，选择发送目标和运行 Worker，在「Pipeline → 样本调试」验证后保存草稿，再发布。聚合模板的目标须支持 metric；缓存与窗口使用有界内存，按 Worker、流发布版本及输入类型隔离，重启清空。

在数据流列表点击「导出配置」，选择「已保存的草稿」或「最近发布的配置」，下载 JSON。未保存的编辑内容不在导出范围内。文件使用 `format: "flowport.flow"`、`version: 1`，包含来源设置、各数据类型的 Pipeline、默认及分流目标引用、Lookup 绑定、队列容量和 ACK 策略；不包含共享目标的连接配置、Lookup 内容和同步凭证、运行位置、队列、采集游标、发布历史或内存状态。这是可复用配置，不能代替完整备份。

连接敏感字段（如 Token、密码、headers、URL、连接字符串、私钥）会递归移除，并列在 `removed_fields` 中。脚本、SQL 查询与自定义配置中的字面值原样保留，分享前必须检查。导入时再次移除这些敏感字段，不使用 `********` 恢复任何旧凭证。

导入步骤：

1. 在目标工作空间先创建所需的发送目标和 Lookup 资源；Lookup 内容通过资源页单独上传或同步。
2. 打开「新建数据流 → 导入配置」，选择最大 2 MiB 的 JSON 文件。系统检查格式版本、Source 类型与文件结构，展示摘要和被移除字段。
3. 为每个默认／分流目标与 Lookup 引用显式选择本地资源；所有引用完成映射后进入配置。不会按同名或同 ID 自动绑定，也不会创建或覆盖共享资源。
4. 检查名称、来源连接、认证、运行位置、队列容量及规则。Lookup 的自动更新策略和固定版本原样保留；固定版本必须在所选资源中存在且兼容，可在 Pipeline 的 Lookup 面板确认或调整。
5. 运行样本，保存为新草稿，再显式发布。仅选择文件或进入配置不会保存、启动接入或修改原流。新流使用新 ID，重置发布版本和运行状态，不继承采集进度，消费类 Source 的起始位置须重新核对。

REST：`GET /api/v1/flows/{id}/export?configuration=draft|published` 返回脱敏配置包，默认 draft；`POST /api/v1/flows/import-preview` 以整个包为请求体，返回规范化配置及完整依赖清单，不写入存储。完成依赖映射后，为 Flow 指定新 ID，通过现有 PUT 草稿和 POST 发布接口生效。两者均沿用认证和 2 MiB 普通管理请求限制；导出需要 read，导入预检需要 write，保存和发布沿用审计。MCP 对应 `exportFlow`、`previewFlowImport`；场景模板位于 UI，脚本语义见 [Pipeline 使用](pipeline.md)。

导入页会显示资源映射进度，内容滚动时底部操作按钮保持可见。检查文件时可取消或更换文件，旧请求的响应不会覆盖新选择。Lookup 列表只在本次窗口打开期间复用；加载失败或资源变化时，点击「刷新资源」即可，无需重新上传文件，文件摘要和已选发送目标会保留。关闭导出窗口也会取消尚未完成的下载请求。
