# Lookup 数据富化

[FlowPort 0.2.0](../../README.zh-CN.md) · [使用指南](https://flowport.pages.dev/docs/pipeline/)

Lookup 是可管理、可同步、可版本化的本地查询资源。管理端获取完整快照并验证，Worker 下载已验证的不可变文件；处理事件时不连接外部数据源。数据源凭证仅保存在管理端，所有节点仍使用单二进制部署。

以下截图于 2026-10-20 从 0.2.0 候选构建的英文界面实拍，使用隔离实例与合成数据；所示界面已包含在 0.2.0 中，截图清单保留拍摄构建的原始信息。示例地址与计数仅作说明，点击图片可查看大图。

## 创建与使用

在「Lookup」页创建资源，选择上传、HTTP(S)、S3 兼容存储、PostgreSQL 或 MySQL。上传 CSV、CSV.GZ 或用户提供的 MMDB；CSV 使用 UTF-8、唯一非空列名，每列内容按字符串处理。资源页提供查询预览、同步结果、历史版本、引用流和 Worker 实际版本。

左侧搜索和选择资源，右侧按任务分为三个页签：「资源配置」只展示当前来源需要的字段，认证、TLS 和高级参数默认折叠；「试查」选择匹配方式、查询列并输入值，以表格查看结果和实际版本；「版本与状态」集中查看历史版本、Worker 安装情况及引用流。同步频率可直接选择常用周期，也可自定义。未保存修改会在离开时提示，保存后才可上传、同步或回滚。

编辑长表单时，保存操作栏保持可见。新建资源会突出下一步上传或同步；上传成功或首次手动同步后自动进入试查。连接地址中的星号表示沿用已保存值，输入新地址可替换。认证请求头接受空对象或值全部为字符串的 JSON 对象。

在数据流的 Pipeline 页添加绑定，选择自动更新或固定版本，明确输入 Field/Tag、查询列、输出列及 Field/Tag 映射。点击「插入脚本」后可将调用移动到源码所需位置。函数执行映射并返回命中布尔值，名称必须是字符串常量；配置面板与脚本共用绑定定义。先保存草稿，再发布。

```ppl
if lookup("services") {
  add_key(enriched, true)
}
```

在样本工作台的 Lookup 视图查看实际数据版本、有界命中行及诊断。Lookup 自身不丢弃事件，未命中保留原记录；过滤、分流继续使用现有 Pipeline 条件与 Tag 路由。

![Lookup 资源页集中管理来源配置、当前版本与同步状态；高级选项默认收起。](https://flowport.pages.dev/assets/screenshots/lookup-resource.webp)

*Lookup 资源页集中管理来源配置、当前版本与同步状态；高级选项默认收起。*

## 完整示例：服务归属补全

本例根据日志的 `service` 字段补充所属团队、业务等级和成本中心。操作顺序为：创建资源 → 上传数据并试查 → Pipeline 添加绑定 → 脚本调用 → 样本调试 → 发布与更新。各语言版本共用以下样本，CSV 中的中文值保持原样，方便直接复制并核对结果。

### 1. 准备 CSV

将以下内容保存为 UTF-8 编码的 `services.csv`。第一行是列名，`service` 是本例唯一的查询键，每个值只能出现一次。

```csv
service,team,level,cost_center
payment,交易组,核心,FIN
search,搜索组,普通,SEARCH
gateway,基础设施组,核心,INFRA
```

### 2. 创建资源并试查

进入「Lookup → 新增资源」，填写以下配置，然后点击「保存配置」。

| 配置项 | 值 |
| --- | --- |
| 名称 | `服务归属表` |
| 数据来源 | 文件上传 / API |
| 文件格式 | CSV |

点击「上传完整版本」，选择 `services.csv`。上传成功后自动进入「试查」：匹配方式选择「精确匹配」，查询列填 `service`，查询值填 `payment`，应命中以下行。

```json
{
  "service": "payment",
  "team": "交易组",
  "level": "核心",
  "cost_center": "FIN"
}
```

资源页试查只验证查询数据，此时还没有把资源接入数据流。

![试查以 service=checkout 精确匹配，返回团队、业务等级与成本中心，并显示实际数据版本。](https://flowport.pages.dev/assets/screenshots/lookup-query.webp)

*试查以 service=checkout 精确匹配，返回团队、业务等级与成本中心，并显示实际数据版本。*

### 3. 在 Pipeline 中绑定资源

进入要处理的「数据流 → Pipeline」，选择日志数据类型 `logging`，展开「Lookup · 数据富化」。输入绑定名称 `service_info`，点击「添加绑定」，按下表配置。

| 配置项 | 值 |
| --- | --- |
| Lookup 资源 | `服务归属表` |
| 数据版本 | 自动更新 |
| 匹配方式 | 精确匹配 |
| 忽略大小写 | 不勾选 |
| 写入规则 | 仅补充缺失值 |

输入键配置一行，读取事件的普通字段 `service`，查询 CSV 的 `service` 列。

| 输入类型 | 输入名称 | 查询列 |
| --- | --- | --- |
| Field | `service` | `service` |

若实际输入中的 `service` 是 Tag，应将输入类型改为 Tag。普通 JSON 顶层字段不会自动变成 Tag。

输出映射配置三行，分别勾选「默认值」并填写以下内容。

| 输出列 | 输出类型 | 输出名称 | 默认值 |
| --- | --- | --- | --- |
| `team` | Tag | `team` | `未归属` |
| `level` | Tag | `level` | `普通` |
| `cost_center` | Field | `cost_center` | `UNKNOWN` |

`team` 和 `level` 写入 Tag，供后续分流使用；`cost_center` 写入普通字段。

![Pipeline 绑定读取 service 字段，将查询列显式映射到 team、business_level 和 cost_center Tag。](https://flowport.pages.dev/assets/screenshots/lookup-binding.webp)

*Pipeline 绑定读取 service 字段，将查询列显式映射到 team、business_level 和 cost_center Tag。*

### 4. 插入脚本调用

如果只需要补充字段，完整脚本就是以下一行，也可点击「插入脚本」生成。

```ppl
lookup("service_info")
```

如果还需要标记是否命中，用下面的脚本替换这一行。两份脚本二选一，不要保留重复调用。

```ppl
if lookup("service_info") {
  set_tag("lookup_result", "matched")
} else {
  set_tag("lookup_result", "unmatched")
}
```

`lookup()` 执行输出映射，同时返回是否命中。未命中后即使填充了默认值，返回值仍为 `false`。参数 `"service_info"` 是 Pipeline 的绑定名称，不是资源显示名称 `服务归属表`，必须直接写成字符串常量。

若前面的处理步骤需要解析日志或提取 `service`，把调用放在提取完成之后。

### 5. 运行样本并核对结果

点击「样本调试」，使用上面的条件脚本，粘贴以下输入 JSON，再点击「运行样本」。

```json
[
  {
    "service": "payment",
    "message": "订单支付成功",
    "amount": 128
  },
  {
    "service": "search",
    "message": "搜索请求完成"
  },
  {
    "service": "unknown_service",
    "message": "新服务启动"
  }
]
```

三条记录均保留，原有字段保持不变，预期新增内容如下。

| 输入 service | Tag：team | Tag：level | Field：cost_center | Tag：lookup_result |
| --- | --- | --- | --- | --- |
| `payment` | `交易组` | `核心` | `FIN` | `matched` |
| `search` | `搜索组` | `普通` | `SEARCH` | `matched` |
| `unknown_service` | `未归属` | `普通` | `UNKNOWN` | `unmatched` |

在「处理后」检查字段及 Tag，切换到「Lookup」查看实际数据版本、命中行和诊断。未命中不会自动过滤，默认值也不会把未命中变为命中。

「仅补充缺失值」会保留已有的同名字段或 Tag，空字符串也算已有值。若查询表应覆盖原值，将写入规则改为「覆盖已有值」。

![样本工作台展示本次使用的 Lookup 数据版本与命中行；预览不会投递业务数据。](https://flowport.pages.dev/assets/screenshots/lookup-preview.webp)

*样本工作台展示本次使用的 Lookup 数据版本与命中行；预览不会投递业务数据。*

### 6. 按结果分流或过滤

要将核心业务送到单独目标，在数据流的「发送目标」步骤开启「按 Tag 分流」，配置以下规则。

| 条件 | 发送目标 |
| --- | --- |
| Tag `level` 等于 `核心` | 已配置的核心业务目标 |
| 未命中规则 | 已配置的默认目标 |

分流读取 Pipeline 处理后的 Tag。多条规则按顺序取首条命中；未命中规则时使用默认目标。可在样本工作台的「路由预演」检查目标选择，详见 [组合 Tag 分流](https://flowport.pages.dev/docs/pipeline/)。

如果业务明确要求只保留查询表中存在的服务，可用以下脚本替换前面的脚本。它会主动过滤未命中的事件，普通富化场景无需使用。

```ppl
if !lookup("service_info") {
  drop()
}
```

### 7. 发布并更新查询数据

核对样本后，确认来源和发送目标已配置，点击「保存草稿 → 发布数据流」，并在运行视图确认 Worker 已安装配置。样本调试不发送数据；真实投递仍需检查目标收据。

例如，将 CSV 中 `payment` 的团队改为 `交易平台组`，重新上传完整 CSV：

- 绑定选择「自动更新」时，Worker 安装新数据后，新接收的批次使用新版本，无需重新发布流；Worker 之间允许短暂版本差异。
- 已入队的旧批次继续使用接收时固定的版本，结果不会随查询表更新而改变。
- 绑定选择「固定版本」时，继续使用指定版本；修改版本选择并重新发布后才切换。

「自动更新」决定绑定跟随哪个数据版本；资源的「自动同步」决定何时从外部来源获取数据。文件上传 / API 不会监视电脑上 `services.csv` 的变化，需重新上传。若需要定时刷新，可将资源来源改为 HTTP(S)、S3、PostgreSQL 或 MySQL，保持列结构并启用「自动同步」；Pipeline 绑定和脚本可沿用。同步失败会继续使用最后有效版本。

## 四种匹配

- **Exact**：单键或最多四个复合键，默认区分大小写；忽略大小写必须显式选择。构建索引时拒绝重复查询键。整数保留十进制文本，禁止将输入浮点数隐式转换为查询键；先用现有 Pipeline 转换函数进行显式转换。
- **CIDR**：支持 IPv4/IPv6，默认最长前缀，也可选择表中首条或全部。相同前缀按表顺序取首条。
- **Regex**：使用预编译 Go RE2 正则，按表顺序取首条或全部；不支持环视、回溯引用及所谓正则最具体匹配。
- **MMDB**：由数据库执行最长前缀 IP 查询。支持国家、地区、城市、ASN、组织预设，以及 `country.iso_code`、`subdivisions.0.names.en` 等字段路径。数据库由用户提供，未提供的字段可用映射默认值补充。

Exact 示例：

```csv
service,environment,team,level,cost_center
payment,production,交易组,核心,FIN
payment,staging,测试组,普通,QA
```

CIDR 示例，输入 IP 映射 `network`：

```csv
network,team
10.0.0.0/8,内网
10.8.0.0/16,交易组
2001:db8::/32,IPv6 示例
```

Regex 示例，输入字符串映射 `pattern`：

```csv
pattern,class
^/api/payment/,支付
^/api/,API
```

MMDB 绑定示例：

```json
{"resource_id":"geo","mode":"mmdb","keys":[{"column":"","kind":"field","name":"client_ip"}],"outputs":[{"column":"country.iso_code","kind":"tag","name":"country"},{"column":"autonomous_system_number","kind":"field","name":"asn"}]}
```

输出默认只补充缺失值，空字符串是已有值；可显式覆盖，并为未命中或缺少的输出列设置默认值。全部匹配最多 64 行，结果按表顺序输出，每个映射列写为 **JSON 数组字符串**，只能写 Field，不能写 Tag，不扩展 Point 类型。超过 64 行时整次 Lookup 不写字段、不应用默认值，返回未命中并记录 `match_limit` 诊断；Regex 输入超限使用 `regex_input_limit`。

## 自动同步与完整性

默认每 15 分钟检查，可设为 60–86400 秒；可立即同步，同一资源不并行，管理端最多两个同步任务，每次总时限 60 秒。失败按下一周期重试。HTTP 支持认证头、TLS、ETag/Last-Modified，拒绝跳转；S3 指定 Bucket/Key，可选对象版本，不扫描桶。

SQL 使用只读账户，在只读 Repeatable Read 事务中执行一条 SELECT。首期查询不允许分号，不分页、不拼接多次查询、不做 CDC。数据库整数及精确数值按文本保存；中断、错误或超限使整个候选作废。SQL 生成 CIDR/Regex 规则时必须配置唯一、非空、整数类型的顺序列，完成读取后再按其数值排序。权限和数据库函数行为仍须由源数据库的只读账号约束。

同步顺序是完整获取、结构及运行绑定兼容性校验、索引构建、持久化、分发、Worker 安装后切换。相同内容不生成新版本，成功的未变化检查仍更新新鲜度。空表默认拒绝；缺列、重复 Exact 键、无效索引、容量不足都保留最后有效版本。超过两个周期没有成功检查显示过期状态，但不停止本地查询。

## 批次与版本

流配置版本、Lookup 数据版本和批次实际版本分别记录。自动更新不重新发布流；各 Worker 验证完成后，在后续批次的入队事务中固定版本。集群允许短暂版本差异，不保证同时切换。上游不能指定批次使用的 Lookup 版本。

同一批次、所有 CDC 分块和崩溃恢复都使用接收时固定的版本。已完成处理的发送积压重发原结果。固定版本通过正常流发布生效。历史版本激活会暂停资源自动同步，恢复时须在「资源配置」中重新启用「自动同步」并保存，避免下一轮覆盖回滚结果。

首次没有有效版本拒绝发布或启用流。队列引用的资源缺失或损坏时暂停该流相关处理并尝试重新获取，保留载荷；资源不可用不是普通未命中，也不是可释放输入的 Pipeline 失败。管理失联时使用本地完整版本，非独占接入及共享消费沿用原批准，独占采集仍受原任务租约约束。

## 容量、安全与恢复

| 项目 | 初始保护上限 |
| --- | --- |
| CSV/SQL 规范化内容 | 32 MiB、100000 行、64 列 |
| Regex | 1000 条、每模式 2 KiB、每输入 64 KiB |
| MMDB | 128 MiB |
| 每进程候选、加载及索引预算 | 256 MiB |
| 每节点 Lookup 文件 | 1 GiB |

这些是保护值，不是生产容量承诺。解压、构建、并发同步和仍被使用的旧版本都占用预算，可能在达到文件上限之前拒绝更新。当前版本、固定配置、队列、在途执行和 Worker 已获准版本受到保护，保留最近五个无引用历史版本。Lookup 更新不会通过淘汰业务队列腾空间。整个 Pipeline 仍受单条执行时间预算约束。

元数据读取沿用 read 权限；内容读取、试查及修改要求 write。凭证脱敏返回 `********`，修改记录沿用现有审计，不记录完整内容或凭证。大文件使用独立的流式上传接口，普通管理请求仍为 2 MiB；MCP 仅管理、同步、试查和读取状态，文件上传下载走 REST。

资源文件在 `native/lookups/` 独立加密保存，配置与队列仅存版本引用。控制协议升级为 **v6**，持久化检查点升级为 **格式 3**。管理端与全部 Worker 必须协调升级；旧程序拒绝新格式。停机后用完整备份工具备份每个节点的整个数据目录和 `master.key`，恢复必须包含资源文件。降级必须恢复升级前完整备份，不能删除引用或只替换可执行文件。

自动同步以 `system` 操作者写入审计。Worker 状态分别显示自动更新使用的版本和已安装版本集合，后者包括固定绑定及队列保留的历史数据。字段映射序列化沿用现有 32 MiB 批次输出上限，按 JSON 转义的保守大小在分配前检查。

Point 的键名唯一；输出映射不能重名，包括 Field/Tag 之间。仅补缺失模式保留同名的已有字段或 Tag；覆盖模式按显式目标类型写入。MySQL 的一致快照要求使用 InnoDB 等支持事务快照的表。
